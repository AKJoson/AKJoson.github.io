# CherryBLOG

**写代码，也写生活。** 技术笔记、日常随想与读书感悟。

博客：<https://akjoson.github.io> · 仓库：<https://github.com/AKJoson/AKJoson.github.io>

当前目录就是博客的写作和发布项目。只需要 **Node.js 20 或更新版本**；Markdown 解析器已随项目保存，**不需要 npm install**。

## 平时怎么写

在当前目录打开终端，新建一篇草稿：

```sh
npm run new -- 计算机 "我的技术笔记"
# 也可以放入计算机的子分类
npm run new -- "计算机/组成原理" "存储器层次结构"
npm run new -- "计算机/Kotlin" "协程学习笔记"
npm run new -- "计算机/C++" "智能指针笔记"
# 或者
npm run new -- 日常随想 "十月的小事"
# 或者
npm run new -- 读书感悟 "活着读后感"
```

文件会出现在对应的草稿目录，例如 `草稿/计算机/C++/`、`草稿/日常随想/` 或 `草稿/读书感悟/`。用你习惯的编辑器写 Markdown 即可。
也可以复制根目录的 `写作模板.md`，自己新建文章。

文章开头的格式：

```yaml
---
title: "我的技术笔记"
date: "2026-10-02"
tags: ["Android", "源码阅读"]
summary: "用一两句话介绍文章，显示在首页和分类列表中。"
---

## 正文标题

从这里开始写。
```

**文件夹就是分类。** 直接在 `文章/` 下新建、重命名或移动文件夹，分类和子分类就会随之调整。文章不需要 `category` 字段；已有的旧字段也会被文件所在目录覆盖。

```text
文章/
├── 计算机/
│   ├── 组成原理/
│   ├── Kotlin/
│   ├── C++/
│   └── 其他计算机笔记.md
├── 日常随想/
└── 读书感悟/
```

例如 `文章/计算机/C++/智能指针.md` 属于“计算机 / C++”，也会出现在“计算机”的汇总页面。直接放在 `文章/` 根目录的 Markdown 会归入“未分类”。

日期使用 `YYYY-MM-DD`。元信息每行一个字段，字符串用双引号，标签用 JSON 数组。完整写作和分类操作见 `写作模板.md`。

图片放在 `images/`，在文章里写 `![图片说明](/images/文件名.png)`。

## 在本地看效果

不启动服务器也可以预览：

```sh
npm run preview -- --drafts
```

用浏览器打开 `.preview-site/index.html`（Finder 中按 `Command+Shift+.` 显示隐藏文件夹）。首页、文章、分类、搜索和主题切换都可以直接查看。修改后再次运行上面的命令。

想要保存后自动构建：

```sh
npm run dev -- --drafts
```

然后打开 <http://127.0.0.1:4173>；保存文章后刷新浏览器。`Ctrl+C` 结束预览。
不加 `--drafts` 时只预览正式文章。预览文件始终写入 `.preview-site/`，不会混入正式网站。

## 发布到 GitHub

1. 写好后把 Markdown 文件从 `草稿/对应分类/` 移到 `文章/对应分类/`。例如读书文章从 `草稿/读书感悟/` 移到 `文章/读书感悟/`，文章归类自动取决于这个目录。
2. 在当前目录运行：

```sh
npm run publish -- "发布：我的新文章"
```

该命令会依次构建网站、检查站内链接、提交项目内的改动、推送当前分支到 GitHub。GitHub Pages 完成部署后，新文章就会上线。默认分支沿用原仓库的 `master`，页面沿用仓库根目录的静态文件和 `.nojekyll`，不需要引入 Hexo 或额外的部署服务。

如果推送被拒绝，按 Git 提示先处理身份认证或远程更新，再重新运行发布命令；脚本不会强制推送。

也可以手动操作：

```sh
npm run build
npm run check
git add -A
git commit -m "更新博客"
git push origin master
```

`草稿/`、原来的 `FreeRTOS/` 和 `.preview-site/` 已被 Git 忽略，不会由发布命令上传。需要公开的文章放进 `文章/`。可选的 `draft: true` 只控制网站展示；若不想上传源文件，应保存在 `草稿/` 中。

## 文件在哪里

| 路径 | 用途 |
| --- | --- |
| `文章/计算机/*.md` | 暂未细分的计算机文章 |
| `文章/计算机/组成原理/*.md` | 计算机组成原理 |
| `文章/计算机/Kotlin/*.md` | Kotlin 文章 |
| `文章/计算机/C++/*.md` | C/C++ 文章 |
| `文章/日常随想/*.md` | 正式日常随想 |
| `文章/读书感悟/*.md` | 正式读书文章 |
| `草稿/` | 仅在本机保存的草稿 |
| `images/` | 文章图片 |
| `site.config.json` | 作者、站点地址、简介和座右铭 |
| `theme/` | 页面公共片段 |
| `assets/theme.css` | 主题样式 |
| `assets/theme.js` | 搜索、主题切换和代码复制 |
| `tooling/` | 离线构建与发布工具 |
| `index.html`、`2025/`、`archives/` 等 | 自动生成的网站，日常不需要手工编辑 |

新文章链接由日期和文件名生成；发布后尽量不要改文件名或日期。如果需要固定地址，可在元信息中添加 `permalink: "/2026/10/02/my-note/"`。原站的六篇文章已经设置固定地址，旧链接继续有效。

## 分类只需调整文件夹

- 新增“旅行”：创建 `文章/旅行/`。
- 新增“Java”子分类：创建 `文章/计算机/Java/`。
- 分类改名：重命名对应文件夹。
- 调整层级：移动子文件夹。
- 调整文章分类：移动该 Markdown 文件。
- 删除分类：先移动需要保留的文章，再删除目录。

不需要修改构建代码、分类配置、文章字段或 HTML。空目录也会显示分类，构建时会自动添加 `.gitkeep`，保证空分类可以同步到 GitHub。隐藏目录不会作为分类。

操作完成后运行 `npm run preview -- --drafts` 预览，或 `npm run publish -- "调整分类"` 直接构建并上传。`npm run dev` 运行期间会自动检测文件夹变动，刷新浏览器即可查看。

正式分类只读取 `文章/`。包含草稿的预览还会临时显示草稿所在目录的分类；这些草稿不会上传。分类页地址随文件夹名称变化。已发布文章只要保持文件名、日期或原有 `permalink`，移动目录也不会改变文章链接。旧的 `/categories/tech/` 等入口继续兼容当前相应目录。
